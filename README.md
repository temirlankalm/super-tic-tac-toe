# Tic³ (Ultimate Tic-Tac-Toe)

Минималистичная веб-игра «супер крестики-нолики» на **Next.js (React 19 + TypeScript + Tailwind CSS v4)**, доступная онлайн на [ttt.temr.dev](https://ttt.temr.dev).

---

## Запуск локально

```bash
cd super-tic-tac-toe
pnpm install
pnpm dev
```

Открой [http://localhost:3000](http://localhost:3000) в браузере.

---

## Приватный Admin Dashboard (`/admin`)

В проект встроен серверный, privacy-friendly дашборд телеметрии и аналитики:
* **Защита доступа**: авторизация по паролю или связке email + пароль, защищенная `httpOnly` сессионная cookie (`sttt_admin_session`), встроенный rate-limiting попыток входа (не более 5 неудачных попыток за 15 минут), заблокирован в `robots.txt` и закрыт `noindex, nofollow, nocache` мета-тегами.
* **Скрытие эндпоинтов**: все `/api/admin/*` эндпоинты отдают `404 Not Found` любым неавторизованным запросам.
* **Privacy-First**: IP-адреса пользователей хешируются с ежедневно обновляемой солью (raw IP никогда не сохраняется), соблюдается сигнал браузера `Do Not Track`.
* **Классификация ботов**: автоматическое разделение краулеров, поисковиков (Google, Bing, Yandex), AI-агентов (GPTBot, ClaudeBot, Perplexity) и headless-инструментов от живых людей.
* **Метрики**:
  * Посетители онлайн прямо сейчас (последние 5 минут).
  * Периоды: сегодня, 7 дней, 30 дней, все время.
  * География: страны (флаги, города, распределение).
  * Поведение: популярность режимов игры (qnet, hard, medium, easy, local 2p, online, daily challenge), процент доходимости партий (completion rate), средняя длительность сессии.
  * Воронка конверсий: визит → старт партии → финиш → шеринг/создание комнаты.
  * Источники трафика: категоризация (Direct, Reddit, Search, Social, Other).
  * Живой поток событий (Live Stream) и выгрузка отчетов в CSV.

### Настройка отдельного поддомена аналитики (`admin.ttt.temr.dev`)

Админ-панель телеметрии изолирована на отдельном поддомене `admin.ttt.temr.dev`. На основном домене `ttt.temr.dev` любые маршруты `/admin*` и `/api/admin*` возвращают **404 Not Found**.

#### 1. Настройка DNS и Vercel Host
1. **DNS (у провайдера домена `temr.dev`):**
   * **Тип записи:** `CNAME`
   * **Имя / Хост:** `admin.ttt` (или `admin.ttt.temr.dev`)
   * **Значение / Цель:** `cname.vercel-dns.com`
   * **TTL:** Auto / 300
2. **Vercel Dashboard:**
   * Открой проект `super-tic-tac-toe` -> **Settings** -> **Domains**.
   * Добавь домен `admin.ttt.temr.dev` (привязан к ветке `main`).

#### 2. Обязательные переменные окружения (Environment Variables)
Укажи в Vercel Dashboard (**Settings** -> **Environment Variables**) для всех окружений (`Production`, `Preview`):

| Переменная | Описание | Пример значения |
|---|---|---|
| `ADMIN_EMAIL` | Обязательный: email администратора | `temirlan122110@gmail.com` |
| `ADMIN_PASSWORD` | Обязательный: пароль администратора | надёжный пароль |
| `ADMIN_PASSWORD_HASH` | (Опционально) SHA-256 хеш пароля | `fffa912e789f...` |
| `ADMIN_SESSION_SECRET` | Обязательный: 32-байтный ключ подписи cookie | случайный 64-символьный hex |
| `ANALYTICS_SALT_SECRET` | Обязательный: ключ для ежедневного хеширования IP | случайный 64-символьный hex |

> [!IMPORTANT]
> Если хотя бы одна из обязательных переменных отсутствует, вход в админ-панель полностью отключается (маршруты отдают `404 Not Found`). Хардкодных паролей и секретов по умолчанию в проекте нет. Сравнение пароля производится в константном времени (`crypto.timingSafeEqual`).

#### 3. Ограничение rate-limiting в Serverless
Встроенный rate-limiting для попыток входа работает in-memory (максимум 5 неудачных попыток за 15 минут на хешированный IP). В serverless-среде (Vercel) состояние памяти сбрасывается при cold start или распределяется по разным изолятам microVM. Для глобальной синхронизации между распределёнными cold-start инстансами рекомендуется подключить Upstash Redis (`@upstash/ratelimit`) или Vercel KV.

Для локальной разработки скопируй `.env.example` в `.env.local`:
```bash
cp .env.example .env.local
```

## Архитектура и дизайн-система

Проект изначально спроектирован так, чтобы дизайн было максимально легко кастомизировать:

* **Токены и цвета** (`src/app/globals.css`):
  * `--bg: #efeeee` — теплый бумажный/каменный холст (`#141719` в темной теме).
  * `--ink: #4e545a` — нейтральный графитовый цвет текста и меток.
  * `--line: rgba(78, 84, 90, 0.16)` — тонкие разделители малых клеток.
  * `--line-strong: rgba(78, 84, 90, 0.38)` — разделители 9 больших секторов.
* **Компоненты** (`src/components/`):
  * `SuperBoard.tsx` — глобальная доска 3×3 с адаптивной пропорцией 1:1.
  * `LocalBoard.tsx` — каждый малый сектор 3×3 и оверлей победы/ничьей.
  * `Cell.tsx` — отдельная клетка с ховером, точкой последнего хода и анимацией появления.
  * `GameStatus.tsx` — статус-бар, мини-локатор активного сектора и элементы управления.
  * `RulesModal.tsx` — лаконичное всплывающее окно с правилами.
* **Логика и AI** (`src/lib/`):
  * `gameLogic.ts` — полная реализация официальных правил Ultimate Tic-Tac-Toe.
  * `ai.ts` — эвристический стратегический бот.
  * `useSuperTicTacToe.ts` — хук состояния с историей ходов, часами и режимами игры.

## Уровень qnet

Четвёртый уровень сложности («qnet») — движок, который целиком работает в браузере, в web worker: никакого сервера и никаких запросов с вашими ходами. Это поразрядный alpha-beta поиск с обученной оценкой позиции (самообучение на партиях против самого себя). Исходники и обучение: <https://github.com/amirlankalm/qnet>.

* `public/qnet/` — готовая сборка движка (ES-модули, без бандлера) и веса сети (`net.bin`, `net.json`); `MANIFEST.json` хранит sha256 и коммит исходников.
* `src/lib/qnet.ts` — клиент worker'а. Любая ошибка тихо переводит игру на прежний ии «hard», партия никогда не зависает.
* Без часов ход обдумывается ~1 секунду. С часами qnet делит оставшееся время на ожидаемое число ходов.
